# README.md и журнал работы с ИИ: гайдлайн для первого курса

## Зачем это нужно

Каждый проект сдаётся с файлом `README.md` в корне репозитория. В нём вы рассказываете, что за сайт сделали, и честно описываете, как пользовались ИИ. Пользоваться ИИ можно; нельзя скрывать, где и как вы им пользовались.

Сейчас вы учитесь верстать, поэтому нам важно видеть, что вы поняли сами, а что за вас сделал ИИ. Использование ИИ само по себе оценку не снижает. Снижает её код, который вы не можете объяснить, и скрытое использование ИИ.

При проверке смотрим на три вещи:

- **Полнота.** Все разделы README заполнены, ссылка на сайт работает.
- **Честность.** Описаны все случаи, когда ИИ помогал вам с кодом.
- **Понимание.** Вы можете своими словами объяснить любую строку своего кода.

## Что такое README.md

README — это текстовый файл с описанием проекта. Его первым видит любой, кто открывает ваш репозиторий на GitHub: GitHub сам показывает его под списком файлов.

Расширение `.md` означает Markdown — простой способ оформлять текст обычными символами. Вот всё, что понадобится:

| Что нужно           | Как написать                                  |
| ------------------- | --------------------------------------------- |
| Заголовок раздела   | `## Название раздела`                         |
| Подзаголовок        | `### Название подраздела`                     |
| Список              | `- пункт`                                     |
| Нумерованный список | `1. пункт`                                    |
| Жирный текст        | `**текст**`                                   |
| Ссылка              | `[текст ссылки](https://адрес)`               |
| Картинка            | `![описание картинки](images/screenshot.png)` |
| Код в строке        | слово в обратных апострофах: `<header>`       |

Между разделами оставляйте пустую строку, иначе Markdown может склеить их в один абзац.

## Как создать README и опубликовать его

### Шаг 1. Создайте файл

1. Откройте папку проекта в VS Code.
2. В корне проекта, рядом с `index.html`, создайте файл `README.md`. Название — заглавными буквами, расширение — строчными.
3. Скопируйте в него шаблон из конца этого гайдлайна.
4. Чтобы увидеть, как файл будет выглядеть на GitHub, нажмите `Ctrl+Shift+V` (на Mac — `Cmd+Shift+V`).

### Шаг 2. Отправьте на GitHub через GitHub Desktop

1. Откройте GitHub Desktop и выберите свой репозиторий.
2. Слева в списке Changes появится `README.md` с зелёным плюсом.
3. Внизу слева в поле Summary напишите, что вы сделали, например: `Добавлен README`.
4. Нажмите **Commit to main**.
5. Нажмите **Push origin** вверху окна.
6. Откройте репозиторий на сайте GitHub и проверьте, что README отображается под списком файлов.

### Шаг 3. Проверьте ссылку на сайт

Ваш сайт публикуется через GitHub Pages. Если он ещё не включён: на сайте GitHub откройте репозиторий, затем **Settings → Pages**, в поле Branch выберите `main` и папку `/ (root)`, нажмите Save. Через пару минут сверху появится адрес сайта — его и вставьте в README.

Обновляйте README каждый раз, когда что-то меняется в проекте, а не только в последний день перед сдачей.

## Что должно быть в README

README состоит из шести разделов в этом порядке.

1. **Название и описание.** Как называется сайт и о чём он, одно-два предложения.
2. **Ссылка на сайт.** Адрес на GitHub Pages. Проверьте, что он открывается.
3. **Скриншот.** Как выглядит главная страница. Положите картинку в папку `images/` и вставьте её в README.
4. **Автор.** Ваше имя и группа. Если работаете в паре — кто какие страницы и блоки делал.
5. **Что я научился делать.** 3–5 пунктов о том, что получилось и что было трудно: например, «разобралась, как работает flexbox», «долго не получалось выровнять меню по центру».
6. **Использование ИИ.** Таблица инструментов, записи о запросах и короткие выводы. Подробно — в следующем разделе.

## Раздел об ИИ: что записывать

Записывайте все случаи, когда вы обращались к ИИ по проекту: чат-боты (GigaChat, YandexGPT, ChatGPT, Claude и другие), подсказки ИИ в редакторе кода, генераторы картинок.

### Часть 1. Таблица инструментов

Одна строка на каждый инструмент, которым пользовались.

| Инструмент | Для чего использовал(а)                       | Уровень помощи |
| ---------- | --------------------------------------------- | -------------- |
| GigaChat   | Объяснил, чем отличаются `margin` и `padding` | 1              |
| ChatGPT    | Помог найти, почему не работает кнопка меню   | 2              |

### Уровни помощи ИИ

| Уровень | Что это значит                                              | Пример                                             |
| ------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 0       | ИИ не использовался                                         | Сверстал(а) шапку сам(а) по макету                 |
| 1       | ИИ объяснил, код написан вами                               | «Как сделать, чтобы картинка не вылезала за край?» |
| 2       | ИИ нашёл ошибку или подсказал небольшой кусок кода          | Подсказал, что забыт закрывающий тег `</div>`      |
| 3       | ИИ написал заметный кусок кода, вы его вставили и разобрали | Скрипт для открытия меню на телефоне               |

Если в проекте есть код уровня 3, отметьте его комментарием прямо в файле:

```html
<!-- ИИ: ChatGPT написал этот блок, я поменяла цвета и отступы. Запись №2 в README -->
```

```css
/* ИИ: GigaChat подсказал этот способ центрирования. Запись №1 в README */
```

```js
// ИИ: ChatGPT написал эту функцию, я разобрался, как она работает. Запись №3 в README
```

В GitHub Desktop, когда коммитите такой код, добавьте в начало поля Summary метку `[ИИ]`, например: `[ИИ] Добавлено мобильное меню`.

### Часть 2. Записи о запросах

Для каждого случая уровня 2 и 3 сделайте запись. Одна запись — одна задача, даже если вы задали ИИ несколько вопросов подряд.

В каждой записи пять пунктов:

1. **Что я хотел(а) сделать.** Своими словами.
2. **Что я спросил(а).** Скопируйте свой главный вопрос к ИИ.
3. **Что ответил ИИ.** Кратко, в одно-два предложения.
4. **Что я изменил(а) сам(а).** Что поправили, что не подошло, что не работало. Если ничего — так и напишите.
5. **Как я понял(а), что это работает.** Как проверяли: открыли в браузере, сузили окно, проверили на телефоне.

Пример записи:

```markdown
### Запись №2 · 03.11.2026

- **Что я хотела сделать:** чтобы меню на телефоне открывалось по нажатию на кнопку.
- **Что я спросила:** «Как на чистом JS сделать, чтобы по клику на кнопку меню показывалось и пряталось?»
- **Что ответил ИИ:** дал скрипт, который добавляет и убирает класс `open` у меню.
- **Что я изменила:** в коде ИИ был класс `.nav`, а у меня меню называется `.menu` — переименовала. Добавила в CSS, как выглядит открытое меню.
- **Как проверила:** сузила окно браузера, нажала на кнопку — меню открывается и закрывается.
```

### Часть 3. Выводы

В конце раздела напишите 3–5 предложений. Ответьте на вопросы:

- В чём ИИ помог больше всего?
- Ошибался ли ИИ? Как вы это заметили?
- Что вы теперь умеете делать сами, без ИИ?

## Правила честной работы с ИИ

Главное правило: вы отвечаете за каждую строку своего кода. Преподаватель может попросить объяснить любой кусок или поменять его прямо на занятии без ИИ.

| Можно                                         | Нельзя                                   |
| --------------------------------------------- | ---------------------------------------- |
| Просить ИИ объяснить тег, свойство или ошибку | Вставлять код, который вы не понимаете   |
| Просить найти ошибку в вашем коде             | Скрывать, что пользовались ИИ            |
| Брать код у ИИ и разбираться, как он работает | Просить ИИ сделать весь сайт целиком     |
| Записывать неудачные попытки                  | Выдавать картинки и тексты от ИИ за свои |

Совет: сначала попробуйте сделать сами 15–20 минут. Если не получается — спросите ИИ, но лучше попросить объяснить, а не написать за вас. Так вы научитесь быстрее.

Если сомневаетесь, нужно ли что-то записывать, — записывайте.
